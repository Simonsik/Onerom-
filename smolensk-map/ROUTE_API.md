# Совместная работа

## Кто меняет файлы

| Задача | Файлы | Ветка |
|---|---|---|
| Отображение маршрута, будущие панорамы, цвета линий и карточки | `route_view.py` | `frontend` |
| Вёрстка, темы и оформление | `index.html`, `style.css` | `frontend` |
| Карта, точки А/Б, запросы API и обработчики интерфейса | `client.py` | `frontend` |
| Построение, проверка и выбор маршрута, HTTP API | `app.py` | `traffic` |
| Оценка камер, заторов, задержек, фильтры объездов | `traffic.py` | `traffic` |
| Импорт данных и проверки сервера | `data/`, `tests/` | `traffic` |

`route_view.py` выполняется в браузере через Brython. `app.py` и `traffic.py`
выполняются на сервере. Браузер не импортирует серверный код.

## Данные маршрутов

`GET /api/route?points=32.035,54.7826;32.055,54.7826&dataset=0&from=07:00&to=09:00`

В запросе и GeoJSON координаты идут в порядке **долгота, широта**.
Leaflet принимает широту, долготу; преобразование выполняется в отображении.
Расстояния — метры, время — секунды.

Пример минимального успешного ответа:

```json
{
  "code": "Ok",
  "routes": [{
    "routeRole": "original",
    "distance": 1000,
    "duration": 120,
    "geometry": {"type": "LineString", "coordinates": [[32.035, 54.7826], [32.055, 54.7826]]},
    "traffic": {
      "duration": 180,
      "delay": 60,
      "coverage": 30,
      "cameras": [],
      "sections": [{"level": "jam", "geometry": [[32.035, 54.7826], [32.055, 54.7826]]}]
    }
  }]
}
```

Сервер возвращает рекомендуемый маршрут **первым**. Интерфейс сохраняет
порядок ответа и первоначально выбирает индекс 0. `active_route` меняется
при нажатии пользователя; это просмотр варианта, а не повторный расчёт.

- `routeRole`: `original` — кратчайший из найденных, `detour` — более быстрый
  объезд, `alternative` — вариант без выигрыша времени.
- `traffic.duration` — время с задержками, `duration` — время сервиса без них.
- `sections[].level`: `free`, `busy`, `jam`, `unknown`.
- `traffic.cameras`: имя `name`, координаты `[широта, долгота]`, скорость
  `speed` (может быть `null`), количество наблюдений `samples`.
- `waypoints` и `trafficContext` — дополнительные сведения сервера.
- Ошибки: HTTP 400/502 и JSON `{"error": "описание"}`; также возможен ответ
  сервиса с `code`, отличным от `Ok`, либо пустым `routes`.

Для панорам бери готовую геометрию из
`self.routes[self.active_route]['geometry']['coordinates']` в `RouteView`.
Обновление панорамы при выборе другого пути подключается в `choose_route`.
Не сортируй маршруты на фронтенде: за рекомендацию отвечает сервер.

Существующие имена полей, единицы и порядок координат сохраняем. Новые
поля можно добавлять; удаление и переименование сначала согласуем.
При добавлении нового браузерного Python-файла нужно один раз добавить его
в `STATIC` в `app.py`, чтобы сервер разрешил загрузку.

## Как объединяться

Сначала объедините этот рефакторинг в `main` через Pull request. Друг забирает
его к себе в `traffic`: `git fetch origin`, затем `git merge origin/main`.
После этого каждый меняет свои файлы, отправляет свою ветку и открывает PR
в `main`. Перед объединением проверяйте карту и запускайте:

```sh
python3 -m unittest discover -s tests -v
```

Панорамный просмотр этим разделением ещё не реализован: выделено место для
его разработки, существующий вид карты и алгоритм выбора сохранены.
